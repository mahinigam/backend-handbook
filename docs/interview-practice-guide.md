# Interview practice guide

Use this workflow alongside Volume 8. It is intended to improve practice quality, not to predict exact questions from any employer.

## A repeatable practice loop

1. **Clarify:** restate inputs, outputs, constraints, and edge cases before coding.
2. **Model:** name the likely data structure or algorithm and explain why it fits.
3. **Baseline:** state a correct simple approach before optimizing.
4. **Implement:** write readable code with explicit invariants and meaningful names.
5. **Test:** cover empty inputs, one-element inputs, duplicates, boundaries, and the example.
6. **Analyze:** explain time and auxiliary-space complexity.
7. **Review:** record the mistake, the missed signal, and a follow-up to revisit later.

## Difficulty calibration

- **Easy:** one main pattern, direct implementation, sound edge-case handling.
- **Medium:** selecting between patterns, composing a few operations, or proving an invariant.
- **Hard:** more than one interacting idea, advanced optimization, or non-obvious correctness reasoning.

Difficulty is subjective and should be adjusted after practice.

## Topic sequence

1. Arrays, strings, and hash maps
2. Two pointers and sliding window
3. Stacks, queues, and binary search
4. Linked lists, trees, and heaps
5. Graph traversal and shortest paths
6. Intervals, greedy methods, and backtracking
7. Dynamic programming and mixed review

## Company-specific preparation

Company labels and interview styles change. Use company-tagged practice sets as starting points, not as a guarantee that a particular problem will appear. Prefer official recruiting resources and clearly dated reports for details about current interview loops.

```text
Final invariant:

Auxiliary space:

```

## Responsible use of references

Keep explanations and solutions original. Link to an exercise's source instead of copying its full statement or a third party's editorial. Distinguish confirmed source-backed company associations from general practice recommendations.
